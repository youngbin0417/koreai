# 생활 서비스 기본 연결과 후속 단계

강남언니·당근마켓·마켓컬리·쿠팡·토스의 연결 기반을 제공합니다. 당근·쿠팡·토스는 기존 조사 목록의 ID를 유지했고, 강남언니·마켓컬리 추가 시 조사 대상은 52개였습니다. 이후 [앱·API 확장 계획](APP_API_BACKLOG.md)의 신규 대상 19개를 더해 현재 카탈로그는 71개입니다.

## 이번 구현

- 서비스별 고정 진입 URL·허용 도메인·공식 근거·확인 날짜·연동 범위.
- 사용자 서비스와 파트너 개발 경로 선택, SQLite 준비 상태 저장·해제·재시작 유지.
- 한국어 관리 화면의 **기본 서비스 연결** 메뉴.
- MCP/HTTP의 연결 상태 조회와 사용자 진입 안내: 5개 커넥터, 10개 `handoff` 행동.
- 준비 전 요청의 `awaiting_user` 대기와 준비 저장 후 재개.
- 사용자 인증이 필요한 작업은 공식 서비스 또는 앱에서 직접 진행.
- 강남언니·당근·마켓컬리의 첫 조회 규격과 비활성 행동 3개, 기본 연결 화면의 정의·접근 조건 표시. [강남언니](GANGNAMUNNI.md), [당근](DAANGN.md), [마켓컬리](KURLY.md)

‘준비됨’은 경로 선택을 저장했다는 의미입니다. 로그인 세션·API 권한을 검증했다는 의미가 아닙니다. `open`은 링크를 반환하며 외부 브라우저를 열거나 페이지를 읽지 않습니다. 링크 안내 성공은 실제 계정 검증과 지원 실적에 포함되지 않습니다.

## 실행 규격

| 행동 | 입력 | 결과 |
|---|---|---|
| `<서비스ID>.connection.status` | `{}` | 준비 상태, 선택 경로, 개발 단계, `accountVerified: false`, `automaticActions: 0` |
| `<서비스ID>.connection.open` | `{}` | 준비한 고정 URL, 사용자 진행 안내, `requiresUser: true`, `externalActionExecuted: false` |

두 행동 모두 기존 `POST /api/jobs`와 MCP 실행 도구를 사용합니다. 클라이언트는 해당 행동을 허용받아야 합니다. `GET /api/connections`도 허용된 서비스만 반환합니다. 준비 저장·해제는 관리자 쿠키와 같은 출처의 요청만 허용합니다. 임의 URL·키·쿠키를 준비 설정이나 행동 입력에 넣을 수 없습니다.

### 강남언니 첫 조회 기능

`gangnamunni.hospitals.search`를 **비활성 제안 행동**으로 등록했습니다. 입력은 `query`, 선택 `region`, `limit`(기본 5·최대 20), 제안 결과는 병원명·제공된 위치 설명·공식 상세 링크입니다. 공급자 요청·인증 규격을 확인한 상태는 아니며 실행 요청은 `NOT_IMPLEMENTED`로 거절합니다. 기존 `connection.open`과 별도 행동입니다.

연결 상태의 `firstRead`에는 제안 입력/결과 JSON Schema·예시·계정 조건·결과 확인 방법·다음 조사 항목을 제공합니다. `stages[].state: defined`는 정의가 생겼다는 뜻이며 자동 조회 지원을 의미하지 않습니다. `automaticActions: 0`과 `accountVerified: false`를 유지합니다. 기본 연결 화면의 **입력·결과 초안과 연결 조건**에서 같은 내용을 볼 수 있습니다.

현재 사용할 수 있는 기능은 `hospitals` 경로를 준비하고 공식 병원 목록을 사용자가 직접 여는 것입니다. API 거절이나 미확인 권한을 기본 연결의 링크 안내 성공으로 바꾸지 않습니다. 공급자에게 확인할 질문과 실제 실행기 활성화 조건은 [강남언니 문서](GANGNAMUNNI.md)에 기록했습니다.

### 당근 첫 조회 기능

`daangn.items.search`를 **비활성 제안 행동**으로 등록했습니다. 입력은 `query`, 필수 `region`, `limit`(기본 5·최대 20), 결과는 제목·가격 원문·표시된 거래 상태·공식 상세 링크입니다. 가격 미제공·가격 제안·나눔을 구분하며 동네 이름을 계정의 인증 위치로 간주하지 않습니다. 규격은 `firstRead`로 제공하고 실행은 `NOT_IMPLEMENTED`로 거절합니다.

`items` 경로는 공식 중고거래 목록의 사용자 직접 확인, `ads-mcp-guide`는 광고주용 공식 MCP 가이드 링크입니다. 둘 다 고정 URL만 반환합니다. 광고 MCP의 서버 주소·인증·한도 근거는 확인했으며 KoreAI의 상위 MCP OAuth·실제 광고 계정·도구 호환성 검증은 후속 단계입니다. 소비자 조회를 광고 MCP로 우회하지 않습니다. [당근 정의·연결 조건](DAANGN.md)

### 마켓컬리 첫 조회 기능

`kurly.products.search`를 **비활성 제안 행동**으로 등록했습니다. 입력은 `query`, `limit`(기본 5·최대 20), 결과는 상품명·옵션·가격 원문과 조건·품절/배송 안내·공식 상세 링크입니다. 시작가와 미확인 가격을 구분하고 옵션 미선택 총액 0원을 상품 가격으로 사용하지 않습니다. 주소별 배송은 `not_verified`를 유지합니다.

`products`는 공식 홈에서 상품을 사용자가 직접 찾는 경로이고 `logistics-auth`는 KLS 물류 인증 안내입니다. 기존 `consumer`·`logistics` 경로도 유지합니다. KLS의 물류 상품/재고를 소비자 상품·구매 가능 상태로 간주하지 않습니다. 제안 규격은 `firstRead`로 제공하고 실행은 `NOT_IMPLEMENTED`로 거절합니다. [마켓컬리 정의·연결 조건](KURLY.md)

## 다음 단계

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 1. 기본 연결 | 서비스 등록·경로 선택·상태 조회·사용자 진입 | 이번 구현 |
| 2. 조회 | 먼저 제공할 조회 행동과 입력·출력을 정의 | 공식 제공·허용 범위, 계정 권한, 실제 결과 검증 |
| 3. 초안·확인 | 실제 데이터로 작업 초안을 만들고 사용자 수정 흐름 정의 | 초안이 외부 전송을 수행하지 않음, 수정된 내용이 승인 대상에 반영됨 |
| 4. 승인 후 실행 | 서비스별 쓰기 행동과 완료 확인을 정의 | 대상·내용 승인, 멱등 처리, 불확실한 결과 대기, 실제 계정 검증 |

조회·게시·주문·예약·금융 업무의 세부 행동은 해당 단계에서 하나씩 확정합니다. 서비스별 범위는 서로 다를 수 있습니다.

## 개발 절차

1. `src/connectors/lifestyle/<서비스ID>.ts`의 경로·근거·제약을 갱신합니다.
2. 새 기능은 별도 행동 ID와 실행기로 등록합니다. 기본 연결 행동을 외부 쓰기로 바꾸지 않습니다.
3. 계정 키는 엔진 암호화 저장소를 사용하고 필요한 행동·계정 권한을 선언합니다.
4. 외부 부작용을 만드는 행동은 `write`, 전송 직전 `dispatch()`, 결과 확인 규칙을 선언합니다.
5. 계정·승인·중복·응답 유실을 검증한 뒤 실제 서비스 증거를 별도로 기록합니다.

# 구조와 실행 원칙

## 구성

- `src/core`: SQLite 저장소, Windows DPAPI, 권한·작업 엔진, OAuth, 단일 실행 잠금.
- `src/connectors`: 공식 API 요청·응답 변환, 고정 브라우저 레시피, 기존 MCP 가져오기.
- `src/http.ts`: 루프백 HTTP API·관리자 세션·정적 UI·운영자 소유 시험 사이트.
- `src/mcp.ts`: 외부 에이전트의 stdio 요청을 같은 HTTP 작업 엔진으로 전달.
- `ui`: 한국어 React 관리 화면.

`Action`은 입력 스키마, 서비스·커넥터 ID, 효과(`read`/`write`), 계정 종류, 필수 키, 공급자 권한, 허용 도메인, 버전, 출처, 검증 상태와 결과 확인 방법을 선언합니다. 모든 어댑터는 같은 `Executor` 인터페이스를 사용합니다.

## 승인과 멱등성

클라이언트가 행동·계정에 대한 권한을 모두 가져야 요청을 만들 수 있습니다. 비밀 키는 실행 직전에만 복호화합니다. 외부 전송 직전에도 권한을 다시 확인합니다.

쓰기는 항상 먼저 저장하고 승인을 기다립니다. 승인 다이제스트에는 행동 ID·커넥터 버전·계정·입력·내용 버전이 포함됩니다. 수정하면 다이제스트와 기존 승인을 버립니다. MCP에는 승인 도구가 없습니다.

멱등키에는 SQLite의 `(client_id, idem)` 고유 제약을 적용합니다. 요청의 정규화된 내용 해시가 다르면 같은 키를 재사용할 수 없습니다. 멱등 기록은 작업 DB와 함께 유지됩니다.

공급자에게 전송하기 직전에 `dispatched`를 저장합니다. 쓰기 중 연결 유실·시간 초과·전송 후 취소는 `needs_review`로 남깁니다. 공급자의 명시적인 401/403은 `awaiting_auth`입니다. 자동 재시도는 수행하지 않습니다. 동일 키는 기록된 작업을 반환합니다.

재시작 시 진행 중이던 쓰기가 전송됐으면 결과 확인을 요구합니다. 읽기와 전송 전 작업은 사용자 재개를 기다립니다. 자동으로 외부 쓰기를 재실행하지 않습니다. 하나의 데이터 폴더에 엔진 두 개가 동시에 복구·실행하지 않도록 잠금 파일을 먼저 획득합니다.

## 브라우저와 외부 데이터

API 연결이 거절됐다고 브라우저로 대체하지 않습니다. 브라우저 행동은 별도의 등록된 레시피입니다. 전용 프로필을 사용하고 시험 사이트의 출처만 허용합니다. 선택자·레시피 버전·입력값·결과 영수증을 검사합니다.

페이지 내용은 외부 데이터입니다. 페이지의 문자열을 코드, 권한, 승인 지시로 실행하지 않습니다. 렌더링은 React 텍스트 출력으로 처리합니다. 실제 서비스 레시피는 별도 허용 범위·인증·실행 결과 확인 검토를 거쳐 추가합니다.

## 기존 MCP

운영자가 URL과 가져올 도구 이름을 지정합니다. 도구의 JSON Schema를 입력 검증에 사용하지만 `readOnlyHint`는 신뢰하지 않습니다. 가져온 도구는 모두 쓰기 승인 절차를 거칩니다. 서버 인증값은 DPAPI로 저장하고 반환값에서 제거합니다.

이 버전은 신뢰하는 운영자가 선택한 MCP 서버를 연결하는 개인용 알파입니다. 임의 코드 패키지를 내려받아 설치하는 플러그인 마켓이나 다중 사용자 서버는 제공하지 않습니다.

## 저장과 지표

SQLite 스키마 v1은 계정·클라이언트·OAuth 상태·검증 기록·운영 설정을 종류별 레코드에 저장하고, 작업은 별도 테이블에 저장합니다. WAL과 busy timeout을 적용합니다. 스키마 변경 시 별도 순차 마이그레이션이 필요하며 하위 버전 호환을 가정하지 않습니다.

최근 작업 목록은 1,000건까지 반환하며 누적 지표는 전체 작업을 기준으로 계산합니다. 운영 통계는 성공·실패·결과 확인 필요·사용자 개입 횟수로 나눕니다. 원격 분석 전송은 없습니다. 지표 계산은 로컬 알파 규모에 맞춰 전체 기록을 읽는 방식이며 대규모 운영에서는 집계 테이블로 옮길 수 있습니다.

## 모의 검증과 실제 검증

검증 기록은 `mock`과 `live`를 구분합니다. 기본 서비스는 공식 응답을 검사한 실제 API 호출 성공이 있을 때 `account_verified`가 됩니다. 같은 버전에 대한 실제 성공 기록이 있을 때 운영자가 `supported`를 지정할 수 있습니다. 브라우저 시험 사이트 성공·사용자의 수동 결과 확인만으로 실제 서비스 지원 실적을 올리지 않습니다.

# 치지직 라이브·채널 조회

확인: **2026-10-19**. 공식 API의 Client 인증으로 공개 정보 두 행동을 제공합니다. 구현된 실행기·모의 시험과 실제 사용자 앱 검증은 구분합니다.

## 계정 연결

1. [치지직 개발자센터](https://developers.chzzk.naver.com/)에서 본인 애플리케이션을 등록하고 API 이용 조건과 접근 권한을 확인합니다.
2. **연결 계정 → 계정 연결 → 치지직 개발자 앱**에서 `clientId`·`clientSecret`을 입력합니다. 네이버 검색 앱 키나 방송 스트림키는 사용하지 않습니다.
3. 필요한 **치지직 라이브 목록 조회**, **치지직 채널 정보 조회** 권한을 선택합니다. 계정과 두 키는 기존 로컬 암호화 저장소에 저장됩니다.
4. **확장 계획 → 치지직**에서 조회 기능을 선택합니다. HTTP·MCP·DeepSeek에서도 해당 행동과 계정을 함께 허용해 사용합니다.

이번 행동은 Client 인증을 사용합니다. 사용자 OAuth·채팅 발송·후원·사용자별 구독자/팔로워 정보·방송 설정과 스트림키는 후속 범위입니다. 문서의 애플리케이션 운영 정책도 확인하세요. [인증·공통 응답 규격](https://chzzk.gitbook.io/chzzk/chzzk-api/tips)

## 라이브 목록: `chzzk.lives.list`

[공식 라이브 문서](https://chzzk.gitbook.io/chzzk/chzzk-api/live)에 따라 현재 진행 중인 라이브의 **한 페이지**를 조회합니다.

```json
{"size":20}
```

| 입력 | 의미 |
|---|---|
| `size` | 1~20, 기본 20 |
| `next` | 선택 사항. 직전 결과의 `pagination.next`를 그대로 사용. 임의 페이지 번호로 바꾸지 않음 |

결과에는 라이브 ID·제목·채널 ID/이름·시청자 수·연령 제한·태그·카테고리가 포함됩니다. `openedAtRaw`는 공급자 시작 시각 원문입니다. 시간대가 명시되지 않은 값을 임의 변환하지 않습니다. `retrievedAt`은 KoreAI의 조회 시각, `providerUpdatedAt: null`은 자료 갱신 시각 미제공을 뜻합니다.

`pagination.next`가 있으면 필요할 때 다음 요청에 넣습니다. 자동으로 모든 페이지를 호출하지 않습니다. 빈 목록은 해당 페이지의 결과이며 전체 방송 없음이나 특정 채널의 오프라인을 뜻하지 않습니다. 페이지 정보 자체가 없으면 `hasMore: null`로 남깁니다.

## 공개 채널: `chzzk.channels.get`

[공식 채널 문서](https://chzzk.gitbook.io/chzzk/chzzk-api/channel)에 따라 채널 ID로 공개 이름·팔로워 수·인증 마크를 조회합니다.

```json
{"channelIds":["앞 단계 라이브 결과에서 확인한 channelId"]}
```

채널 ID는 1~20개이며 중복을 거절합니다. 이름 검색과 구분합니다. 화면의 예시 ID `00000000000000000000000000000000`은 형식 확인용 가상 값이므로 실제 조회에는 라이브 결과나 본인 채널의 ID를 입력하세요. 요청 배열은 반복 `channelIds` 쿼리로 인코딩합니다. 실제 앱을 이용한 다중 ID 응답 검증은 남아 있습니다.

`channels`는 반환된 채널, `notReturnedChannelIds`는 이번 응답에 없는 요청 ID입니다. 미반환을 삭제나 영구 이용 불가로 확정하지 않습니다. 사용자별 팔로우·구독 내역은 포함하지 않습니다.

## 미리보기·실행 결과와 오류

예시·미리보기는 외부에 요청하지 않습니다. 미리보기에는 헤더 이름과 비밀 필드명만 표시하고 키를 조회하거나 출력하지 않습니다. 실제 호출은 고정 HTTPS 도메인 `openapi.chzzk.naver.com`과 두 GET 경로만 사용하며 리디렉션을 거절합니다.

- HTTP 또는 응답 코드 401/403은 `awaiting_auth`입니다. 개발자 앱 키·권한을 확인하고 계정 수정 후 수동 재개하세요.
- 429는 `PROVIDER_RATE_LIMIT`입니다. 호출량과 공급자 한도를 확인하세요. 자동 연속 재시도는 하지 않습니다.
- 400/404/500 등은 공급자 오류로 기록하고 원문 메시지를 전달하지 않습니다. 404를 임의의 빈 정상 결과로 바꾸지 않습니다.
- 정상 응답도 ID·요청 집합·중복·최대 결과 수·숫자·커서 반복을 검사합니다. 추가 필드·내부 지시문·스트림키 등은 결과에서 제외합니다.
- 2MB 응답 제한·30초 제한·취소를 적용합니다. 동일 멱등 요청은 기존 작업을 반환합니다. 쿠키·Client Secret을 모델 결과나 일반 오류에 전달하지 않습니다.

## 검증 상태와 후속

공식 HTTPS의 두 경로에 무효 시험 Client ID/Secret을 넣어 HTTP/JSON 401을 확인했습니다. 실제 유효 앱으로 라이브·채널·다중 ID·다음 커서·한도·권한을 확인하지 않았으므로 배포 지원으로 집계하지 않습니다. 모의 응답의 단위/HTTP 테스트, 실제 Edge의 390px 화면, Ubuntu Node 22.17 실행을 검증 대상으로 관리합니다. [검증 기록](VALIDATION.md#2026-10-19-치지직-조회알라딘-종료-공지-검증)

후속은 실제 앱 검증과 카테고리 조회입니다. 채팅·방송 변경 등 쓰기는 사용자 OAuth·별도 권한·내용 승인·실행 결과 확인 규격을 정의한 뒤 추가합니다.

# 네이버 검색 종료·이용 제한 반영

공식 자료 확인: **2026-10-20** · 반영/검증: **2026-10-21**. 개발자센터의 기존 검색 API와 NAVER API HUB는 별도 제공 경로입니다. 이번 변경은 기존 검색 연동의 중단 처리이며 API HUB에 새 키로 연결한 구현은 아닙니다.

## 공식 확인과 적용

| 범위 | 공식 근거 | KoreAI 적용 |
|---|---|---|
| 쇼핑·책·전문자료 검색 종료 | [종료 공지](https://developers.naver.com/notice/article/32564), [현행 약관 부칙 제2조](https://developers.naver.com/products/intro/terms/terms.md) | `naver.search.shop`, `naver.search.book`, `naver.book.isbn`을 공급자 종료로 중단 |
| 나머지 검색 데이터의 AI 입력·활용 제한 | [검색 특약 2.3](https://developers.naver.com/products/intro/terms/terms.md), 현행 문서 2026-10-07 개정 | `naver.search.news`, `.blog`, `.cafearticle`, `.local`을 이 프로젝트의 AI 전달 방식과 맞지 않아 중단 |
| 기존 검색 API의 이관 유예 | 같은 약관 부칙 제2조 | 신규 신청은 2026-07-30 24시 이후 중단, 기존 이용자의 다른 검색은 2027-06-30 24시까지 유예. AI 이용 허용과 별개 |

쇼핑·책·전문자료는 2026-07-31 24시 종료가 명시돼 있어 기존 이용자도 8월 1일부터 사용할 수 없습니다. 전문자료는 원래 KoreAI에 구현하지 않았습니다. 다른 검색을 중단한 것은 AI 게이트웨이의 이용 방식에 따른 제품 결정이며 공급자 API 자체의 전면 종료를 주장하지 않습니다.

## 제품 동작

- 관리자 카탈로그에는 일곱 행동의 이름·과거 입력 형식·중단 사유·공식 근거를 남깁니다. 계정을 연결해도 실행할 수 없으며 신규 검색 앱 등록/행동 권한 선택에서 제외합니다.
- HTTP/MCP 에이전트의 기능 검색에서 제외하고, 이전 토큰·계정 권한으로 요청해도 전송 전에 거절합니다. 종료는 `SERVICE_RETIRED`, AI 이용 제한은 `PROVIDER_POLICY_RESTRICTED` 오류로 구분합니다.
- 공급자 중단 정보는 `Action.unavailable`에 선언합니다. 일반 운영 중단 해제로 다시 활성화할 수 없습니다. 과거 성공 증거·배포 지원 지정이 있어도 검증 표시는 `suspended`이며 실제 검증/지원 집계에서 제외합니다.
- 재시작으로 대기 중이던 작업을 재개하거나 직접 실행기를 호출할 때도 전송 전에 차단합니다.
- 과거 결과는 관리자 로컬 이력에 보존합니다. 에이전트의 작업 목록/상세에는 결과 본문을 제공하지 않습니다. 기존 대화에 해당 행동이 있으면 이전 결과를 DeepSeek에 재전송하지 않고 새 대화를 안내합니다. 사용자 데이터·키를 자동 삭제하거나 다른 공급자로 옮기지 않습니다.
- 도서의 과거 예시·요청 구조 미리보기는 외부 호출 없이 보존하며 종료 상태를 표시합니다. 실행 가능한 연결이나 신규 초안으로 집계하지 않습니다.

네이버 카페 가입/게시·캘린더는 이 검색 제한 대상에 포함하지 않았습니다. 치지직도 별도 개발자 API입니다. 각각의 실제 계정·제공 조건 검증은 기존 후속 작업으로 유지합니다.

## 집계

현재 카탈로그는 **104개**, 후보는 **64개**입니다. 고용24 지역 코드 추가 후 코드가 보존된 공식 API 정의는 53개이며, 중단 7개를 제외한 구현 집계는 **26개 커넥터·46개 행동**입니다. 계정이나 운영자 설정이 추가로 필요한 행동도 있어 구현 수가 바로 실행 성공 수를 뜻하지는 않습니다.

확장 조회의 활성 정의는 API 31개·공공파일 2개·공개 MCP 5개로 **38개**입니다. 전체 확장 정의 40개 중 도서 2개는 중단 규격으로 보존합니다. OP.GG 공개 MCP와 동물병원·참가격 공공파일은 API 집계와 별개입니다.

2. AI 입력·외부 모델 전달·캐시/보관·출처 표시가 허용되는 계약/상품인지 확인합니다. 기존 개발자센터 키나 제한의 임의 해제만으로 대체하지 않습니다.
3. 허용 범위가 확인되면 새 커넥터로 구현하고 정상·빈 결과·권한/한도·출처·보관과 실제 키 호출을 검증합니다. 문서 확인이나 401/403만으로 제공 여부를 판정하지 않습니다.

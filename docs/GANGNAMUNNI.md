# 강남언니 첫 조회 기능 정의

확인일: **2026-10-15**. 첫 범위는 **병원 이름·지역으로 공개 병원 후보 찾기**입니다. 기능 정의와 비활성 행동을 등록했으며 실제 자동 조회·검색 결과 수집은 아직 제공하지 않습니다.

## 확인한 연결 경로

| 경로 | 확인한 사실 | 구현 경계 |
|---|---|---|
| [기존 공식 주소](https://www.gangnamunni.com/) | 현재 `https://unni.app/`으로 이동 | 사용자 기본 진입 경로를 새 공식 도메인으로 갱신 |
| [공식 병원 목록](https://unni.app/hospitals) | 공식 사이트의 병원 메뉴·공개 목록 경로, HTTP 200 확인 | 사용자가 직접 열고 이름·지역을 확인. 이 페이지의 존재만으로 자동 수집 허용을 판단하지 않음 |
| [병원 파트너센터 설명서](https://docs.channel.io/unni/ko/articles/파트너센터-사용-설명서--3d48f641) | 병원 정보·의사 정보·상담 등 병원 운영 기능 안내 | 병원 운영자 권한을 소비자의 전체 병원 검색·개인 상담내역 권한으로 사용하지 않음 |
| [소비자 사이트 푸터의 이용약관 링크](https://www.notion.so/healingpaper/241120-237d9338d3d4819d9bfbf6012bc999e5) | 공식 사이트가 연결하는 약관 주소 확인 | 이번 조사에서는 본문을 읽지 못했으며 자동 접근 조건은 확인 대기 |

소비자용 검색 API의 인증·엔드포인트·요청 필드·외부 제공 조건은 확인하지 못했습니다. 공개 API가 존재하지 않는다고 단정한 것은 아닙니다. 검색 중 발견한 [healingpaper 이름의 공개 Postman 워크스페이스](https://www.postman.com/healingpaper/healingpaper-s-public-workspace/overview)는 페이지 접근만 확인했고 발행 주체·현재 명세·소비자 권한을 검증하지 못해 실행 근거로 채택하지 않았습니다.

## 행동과 제안 규격

| 항목 | 정의 |
|---|---|
| 행동 ID | `gangnamunni.hospitals.search` |
| 효과 | 읽기 |
| 연결 상태 | `partnership`·`implemented: false`; 공급자 확인 대기 |
| 검증 상태 | 공식 진입·파트너 안내 문서 확인. 계정 검증·API 실행·배포 지원 미수행 |
| 현재 동작 | 카탈로그에서 입력 설명 확인 가능. 실행 요청은 `NOT_IMPLEMENTED`로 거절 |
| 계정 | 소비자 인증 방식 미확인. 자격정보 유형·키·토큰을 임의로 만들지 않음 |
| 유지보수 | KoreAI, 초안 버전 `0.1.0-draft.1` |

입력은 **KoreAI 제안**이며 공급자 요청 형식이 아닙니다.

```json
{"query":"피부과","region":"강남역","limit":5}
```

- `query`: 병원명 또는 진료 분야 검색어, 공백 제거 후 1~100자.
- `region`: 선택 지역·역 이름, 1~80자. 공급자의 지역 코드로 자동 변환하지 않음.
- `limit`: 기본 5·최대 20. 공급자 한도를 확인하기 전의 KoreAI 결과 상한.
- 키·쿠키·임의 URL·환자 식별자 등 추가 필드는 받지 않음.

제안 결과는 `status`, `hospitals[]`, `retrievedAt`, `providerUpdatedAt`입니다. 병원별 `providerId`·`name`·`locationText`·공식 병원 상세 `sourceUrl`만 첫 범위에 둡니다. 식별자·위치·갱신 시각이 제공되지 않으면 `null`로 보존합니다. 검색 결과가 없는 `no_data`와 로그인 필요·접근 거절·통신 실패는 구분해야 합니다.

지역 일치 여부와 중복 식별자, 공식 HTTPS 상세 주소, 병원명·위치 원문을 대조해야 합니다. 표시 순서를 의료 품질 순위로 해석하지 않습니다. 첫 범위에는 시술 가격·할인·이벤트·후기 본문·개인 상담내역·사진·예약을 포함하지 않습니다. 후속 기능은 별도 행동으로 정의합니다.

## 현재 사용할 수 있는 방법

1. **기본 서비스 연결 → 강남언니**에서 첫 조회 기능과 확인 대기 사항을 봅니다.
2. **공개 병원 목록 직접 확인** 경로를 선택하고 **연결 준비 저장**을 누릅니다.
3. **서비스 열기** 또는 **병원 목록 직접 확인** 링크를 열어 사용자가 직접 검색합니다.

HTTP 준비 저장은 `PUT /api/connections/gangnamunni`에 `{"routeId":"hospitals"}`를 보냅니다. 기존 `gangnamunni.connection.open`의 입력은 계속 `{}`이며 선택한 고정 목록 URL만 반환합니다. 이름·지역 검색을 대신 수행하거나 페이지를 읽지 않습니다. `requiresUser: true`, `externalActionExecuted: false`, `accountVerified: false`를 유지합니다.

`gangnamunni.connection.status`와 권한이 있는 `GET /api/connections`의 `firstRead`에서 행동 ID·제안 입력/결과 JSON Schema·예시·계정 조건·다음 확인 사항을 조회할 수 있습니다. 관리자 전용 상태 화면에도 같은 정의를 표시합니다. 준비 저장 후에도 자동 조회 초안은 활성화되지 않으며 실제 지원 수는 증가하지 않습니다.

## 공급자에게 확인할 내용과 활성화 조건

아래는 문의에 사용할 질문 초안이며 외부로 발송하지 않았습니다.

1. 일반 소비자 계정을 위한 병원 검색·공개 정보 조회 API 또는 제휴 제공 경로가 있는가?
2. 병원 파트너 계약과 별개로 어떤 주체가 권한을 받을 수 있고 테스트 환경·키·토큰은 어떻게 발급하는가?
3. 이름·지역 검색, 결과 정렬/페이지/상한, 제공 필드와 식별자, 갱신 시점은 무엇인가?
4. 검색 결과의 로컬 보관·캐시·LLM 전달·출처표시·재사용·삭제·호출 한도 조건은 무엇인가?
5. API가 없을 때 사용자 소유 전용 브라우저에서 자동 조회가 허용되는가? 로그인·추가 인증·화면 변경 시 중단 조건은 무엇인가?

허용된 연결 방식과 현재 규격을 확인한 뒤 별도 실행기·실제 필요한 계정 유형을 구현합니다. 공급자 허용 테스트 환경에서 성공·빈 결과·동명 병원·지역 불일치·로그인 만료·한도·화면 변경을 검증한 후 활성화합니다. 브라우저 대안은 허용 범위와 실제 동작을 확인한 행동에만 적용합니다.

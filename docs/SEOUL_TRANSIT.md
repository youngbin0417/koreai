# 서울·수도권 지하철과 또타라커

확인일: **2026-10-25**. 도착정보·예정 시간표·공식 경로/환승 API와 노선도/또타라커 앱의 기본 연결을 제공합니다. **본인 키의 정상 응답 검증은 대기**입니다. 경로는 별도 공공데이터포털 키와 HTTPS를 사용합니다. 또타라커 실시간 빈칸은 승인된 제공 경로를 확인해야 합니다.

## 도착·시간표 시작하기

1. 서울 열린데이터광장에서 본인 인증키와 각각의 지하철 API 이용 조건·권한을 확인합니다. 기존 따릉이 계정이나 `sample` 키를 자동 사용하지 않습니다.
2. 서버 운영자가 공급자까지의 HTTP 키 전송을 확인하고 **서버 실행 환경에** `KOREAI_ALLOW_SEOUL_SUBWAY_HTTP=1`을 지정한 뒤 재시작합니다. 기본은 차단이며 브라우저·에이전트 입력으로 변경할 수 없습니다. 따릉이 허용 설정과 독립적입니다.
3. **연결 계정 → 서울 지하철 도착·시간표**에서 `apiKey`와 필요한 행동만 허용합니다. 서비스별 키가 다르면 계정을 따로 등록합니다.
4. **확장 계획 → 서울·수도권 지하철**에서 도착 또는 시간표를 선택합니다. 역 이름·조건·계정을 확인하고 키 없는 요청 미리보기 후 실행합니다. 외부 에이전트와 DeepSeek 대화에도 행동·계정을 별도로 허용해야 합니다.

HTTP 구간에서는 키와 응답이 암호화되지 않고 출처 무결성을 확인하지 못합니다. HTTPS 프로브는 이번 환경에서 연결 시간 초과였습니다. HTTP로 자동 폴백하지 않으며 공식 HTTP 경로는 위 운영자 설정 후에만 사용합니다. 키는 서버 실행 시 경로에 한 번 인코딩하고 미리보기·응답·일반 로그에 제공하지 않습니다. 역·필터는 해당 공급자로 전송됩니다. 운영 프록시에서도 키가 포함된 요청 경로를 기록하지 않아야 합니다.

## 지도

**지하철 노선도** 탭 또는 **기본 서비스 연결 → 서울·수도권 지하철 → 국문 노선도 보기**로 들어갑니다. 지하철 조회 조건 화면의 **국문 노선도 확대해서 보기**는 새 창에서 같은 화면을 열어 작성 중인 조건을 유지합니다. 키·계정 연결은 필요 없습니다.

1. **국문 노선도 불러오기 · 10.5MB**를 누릅니다. 사용자가 누르기 전에는 JPG를 다운로드하지 않습니다.
2. **확대·축소**, 확대 비율 슬라이더, **화면 맞춤**, **원본 크기**로 표시 크기를 조절합니다. 화면 맞춤은 왼쪽 위로 돌아갑니다.
3. 휴대폰에서는 지도 안을 손가락으로 밀고, PC에서는 마우스로 끌거나 스크롤합니다. 지도 영역에 초점을 두면 방향키로 이동합니다. 브라우저의 두 손가락 확대도 허용합니다.
4. 다운로드가 실패하면 **노선도 다시 불러오기**를 누르거나 **국문 원본 JPG 열기**, **4개 언어 원본 ZIP 받기**, **서울교통공사 사이버스테이션**을 사용합니다.

[공식 자료](https://www.data.go.kr/data/15120713/fileData.do)는 **자료명 기준일 2025-12-08**인 보관본이며, 출처 페이지 수정일은 **2026-09-10**입니다. 이 수정일을 지도 기준일이나 현재 운행 보증으로 쓰지 않습니다. 국문 JPG는 6142×6142·10,509,901바이트입니다. 공식 ZIP의 `25년 노선도리뉴얼 국문(25.12.).jpg`를 그대로 배포하며 JPG SHA-256은 `8c8dbb0451384a3b703a1709bafc220ca4bc7e4959868ba5bf0f6af6f3151914`입니다.

이용 조건은 **공공누리 제3유형: 출처표시·변경금지**입니다. 원본의 재인코딩·자르기·색상 변경·역/노선 표시 추가 없이 브라우저의 표시 크기·스크롤만 조절합니다. 코드의 Apache-2.0과 이미지 이용 조건을 구분하며 [외부 저작물 고지](../THIRD_PARTY_NOTICES.md)·제품의 `/maps/NOTICE.txt`에 출처·원본 경로·지문을 보존합니다.

뷰어는 정적 원본 열람 기능입니다. API 행동·작업·서비스 검증 증거를 생성하지 않고 구현/지원 수에도 더하지 않습니다. 원본은 배포한 서버의 정적 파일로 제공하며 외부 이미지·iframe·추가 스크립트를 불러오지 않습니다. 로그인·대화·키를 이미지 요청에 별도 매개변수로 붙이지 않습니다. 정적 JPG를 브라우저가 재사용할 수 있지만 오프라인 사용은 보장하지 않습니다.

최신 노선은 [공식 사이버스테이션](https://www.seoulmetro.co.kr/kr/cyberStation.do)에서 직접 확인합니다. 이전 서버 측 접속은 시간 초과였으므로 외부 공식 페이지의 실제 조작은 검증하지 않았습니다. KoreAI의 역 선택은 별도 공식 참조 목록에서 조회 조건을 채우는 방식입니다. 경로·환승은 아래의 공식 API로 조회하며 보관 이미지를 분석하거나 그 위에 역 선택 표시를 덧붙여 그래프를 생성하지 않습니다.

## 역 찾기와 조회 조건 연결

**지하철 노선도 → 역 찾기 · 조회 조건 연결**에서 역 이름 또는 도착정보 역 ID를 검색하고 호선으로 좁힌 뒤 항목을 선택합니다. 동명역은 각각 표시합니다. 예를 들어 신촌 2호선과 경의중앙선은 별도 항목이며 같은 이름을 환승 관계로 판정하지 않습니다.

선택한 역에서 **도착 조회 조건 채우기**, **시간표 조건 채우기**, **사물함 설치 조건 채우기**를 누르면 기존 조회 폼에 검색어를 적용합니다. 이 조작은 외부 호출·작업·승인·권한 추가를 만들지 않습니다. 폼의 내용을 확인하고 **실행 요청**을 눌러 조회합니다.

- 도착: 공식 참조 파일의 역명 검색어를 사용하며 기존 건수·선택 계정을 보존합니다. 파일의 도착 호선/역 ID는 입력에 추가하지 않습니다.
- 시간표: 바로가기는 **1~8호선**으로 한정합니다. 역명·호선을 검색 초안에 넣고 요일·방향·임시·기준 시각·건수·선택 계정을 보존합니다. 이 범위는 바로가기의 확인 범위이며 다른 호선 API의 미제공을 확정하는 표시는 아닙니다.
- 사물함: 바로가기는 설치 자료의 **1~9호선 분류**만 연결합니다. 원문 역명으로 검색하고 호선 분류를 명시적으로 적용하며 페이지는 1로 되돌립니다. 크기·건수는 보존하고 계정은 사용하지 않습니다. 부역명 차이로 0건이면 검색어를 직접 수정하세요. 괄호나 ‘역’을 자동 삭제하지 않습니다.
- 기존 JSON이 깨져 있으면 내용을 유지하고 적용을 거절합니다. 이전에 선택한 계정이 해제되면 다른 계정으로 바꾸지 않고 선택을 비웁니다. 역명·호선을 직접 바꾸면 이전 역을 적용했다는 안내를 숨깁니다.
- 초안은 해당 브라우저 화면의 메모리에서 보존합니다. 새로고침·새 창은 별도 초안이며, 기존 조회 화면에서 연 지도 새 창의 선택을 원래 창에 자동 전달하지 않습니다.

## 실시간 도착

[공식 도착정보 명세](https://data.seoul.go.kr/dataList/OA-12764/A/1/datasetView.do)의 `seoul-subway.arrivals`를 사용합니다.

```json
{"stationName":"서울","limit":5}
```

고정 `http://swopenapi.seoul.go.kr/api/subway/{apiKey}/json/realtimeStationArrival/0/{limit}/{stationName}` 경로입니다. 이름은 공식 표기이며 ‘서울역’을 ‘서울’로 임의 변환하지 않습니다. `limit`는 1~100, 기본 20입니다. 서울시 외 일부 구간은 미제공이며 역별 별칭은 공급자 안내를 확인하세요.

반환한 `rows`는 호선·열차 번호·방향·행선지·도착 메시지·`reportedArrivalSeconds`·`providerCreatedAtRaw`·`ageSeconds`·막차 보고를 제공합니다. 공급자 예보 `0`을 현재 도착으로 단정하지 않고 `adjustedArrivalSeconds`는 `null`입니다. 생성 후 60초 초과·미래 시각은 화면에서 경고합니다. 빈 목록으로 운행 종료·첫차·막차 종료를 추정하지 않습니다. 60초 뒤 작업 결과는 공통 엔진에서 만료되어 모델에 재전송하지 않습니다. 자동 갱신은 하지 않습니다.

## 예정 시간표

[현행 시간표 명세](https://data.seoul.go.kr/dataList/OA-22750/A/1/datasetView.do)의 `seoul-subway.timetable`를 사용합니다. 과거 `SearchSTNTimeTableByIDService`를 새 명세로 오인하지 않습니다.

```json
{"stationName":"서울","lineName":"1호선","direction":"상행","day":"평일","temporary":"N","at":"2026-10-22T09:00:00+09:00","limit":5}
```

고정 `http://openapi.seoul.go.kr:8088/{apiKey}/json/getTrainSch/1/{limit}/%20/{temporary}/{direction}/{day}/{lineName}`과 쿼리 `stnNm/searchDt`를 사용합니다. 역·호선은 **포함 검색**, 방향은 상행/하행/내선/외선, 요일은 평일/주말/상시, 임시는 N/Y입니다. 공휴일·현재 요일을 자동 판정하지 않습니다. `at` 생략 시 실행 시각을 한국 시간으로 변환해 전송하며 요청 미리보기 시각과 실제 실행 시각은 달라질 수 있습니다.

실제 공개 샘플은 명세 공통 설명과 달리 `response.header.resultCode`·`response.body.items.item/pageNo/numOfRows/totalCount` 구조를 반환했습니다. 이를 검증하고 첫 구간만 제공합니다. 전체/수신 수와 잘린 구간을 표시하며 자동 페이지 순회·다음 열차 계산은 하지 않습니다. 공급자 결과는 시간순을 보장하지 않습니다.

예정 출발·도착·유효 시작/종료를 원문으로 보존합니다. 24시 이후 표기는 운행일 기준 시간이며 달력 날짜로 임의 환산하지 않습니다. 기준 시각이 양쪽 유효기간 안인지 `validAtQuery`로 표시하고 기간 미제공은 `null`, 기간 밖은 `false`입니다. **공개 샘플에 2025년 유효기간 자료가 있었으므로 현재 시간표로 판정하지 않습니다.** 실제 운행과 지연·승차 가능도 별도입니다.

## 공식 경로·환승

키는 [환경변수 관리 안내](ENVIRONMENT.md)에 따라 `.env`의 `KOREAI_SEOUL_SUBWAY_ROUTE_SERVICE_KEY`·`KOREAI_SEOUL_SUBWAY_ROUTE_ACTIONS`로 관리할 수도 있습니다. 환경 계정은 파일 수정 후 서버 재시작으로 갱신합니다.

**연결 계정 → 서울 지하철 경로·환승**에서 `serviceKey`에 공공데이터포털 **일반 인증키(Decoding)**를 등록하고 **서울 지하철 경로·환승 조회**만 명시적으로 허용합니다. **확장 계획 → 서울·수도권 지하철**에서 실행합니다. 기존 서울시 도착/시간표 키·따릉이 키는 자동 사용하지 않습니다. HTTPS 호출이므로 `KOREAI_ALLOW_SEOUL_SUBWAY_HTTP` 설정과 독립적으로 실행합니다.

```json
{"origin":"신도림","destination":"서울역","preference":"transfer","includeTimetable":false,"at":"2026-10-25T09:00:00+09:00"}
```

- 행동 ID: `seoul-subway.route`. 공공데이터포털 [서울교통공사_최단경로이동정보 15143842](https://www.data.go.kr/data/15143842/openapi.do)의 현행 Swagger를 기준으로 구현합니다.
- 고정 주소: `https://apis.data.go.kr/B553766/path2/getShtrmPath2`. 같은 페이지에 보존된 과거 `getShtrmPath`·`dptreStnNm` 명세와 구분합니다. 사용자 입력으로 URL을 바꾸지 않으며 리다이렉트·HTTP 우회를 허용하지 않습니다.
- `dptreStn/arvlStn`, `stationValueType=name`, `dataType=JSON`, `searchType=duration/distance/transfer`, `schInclYn=N/Y`로 전송합니다. 출발·도착은 서로 다른 역명 한 개씩이며 호선·도착 역 ID를 보내지 않습니다. 경유/제외역·코드 입력은 이번 버전에 제공하지 않습니다.
- `at`는 시간대 포함 ISO 시각입니다. 생략하면 **실행 시작 시각**을 고정해 Asia/Seoul의 `searchDt=yyyy-MM-dd HH:mm:ss`로 전송하고 결과에 보존합니다. 미리보기 시각과 실행 시각은 달라질 수 있습니다. 기본은 경로만 조회하며 `includeTimetable:true`일 때 공급자 시간표도 요청합니다.
- 개발단계 자동승인·운영단계 심의승인, 개발계정 신청 가능 트래픽 10,000, 무료·이용허락범위 제한 없음으로 고지되어 있습니다. 페이지 수정일은 2026-09-22이고 경로 자료는 수시 갱신 설명과 실시간 갱신 메타데이터를 제공합니다. 실제 적용 한도·이용기간은 승인 계정에서 확인해야 합니다. 갱신 메타데이터를 실시간 운행 보장으로 쓰지 않습니다.

**역 찾기 화면**에서는 1~8호선 항목에 **경로 출발역 조건 채우기 / 경로 도착역 조건 채우기**를 제공합니다. 다른 쪽 역·경로 기준·시각·시간표 포함·선택 계정은 유지하며 외부 조회는 실행 요청 후에만 수행합니다. 이 호선 제한은 검토한 바로가기의 범위이며 API 전체 제공 구간을 뜻하지 않습니다. 원문 역명만 넣으므로 도착 목록의 `서울`과 경로 명세 예시의 `서울역` 등 표기 차이는 직접 확인·수정해야 합니다. 동명역의 호선을 고정하거나 다른 서비스의 역 코드를 확인한 기능은 아닙니다.

결과는 `summary`(m·초·원·환승 횟수), `segments`(양쪽 역명/코드/번호/호선/지선·구간 거리/시간·환승/급행/무정차 원문·열차/시간표), `transfers`(공급자 환승역/호선), 출처·조회 시각을 제공합니다. `providerObservedAt`은 `null`이며 조회 시각을 관측 시각으로 표시하지 않습니다. 시간표 `25:10:00` 같은 표기는 원문 그대로 보존합니다. 공급자 요금은 실제 결제액이 아니며 대기·총 소요를 임의 합산하지 않습니다. UI는 구간 10개씩 로컬 페이지로 표시합니다.

정상 코드·요청한 검색유형/시간표 포함 여부·첫/마지막 역명·인접 응답 구간의 역 코드/역명/호선 연속성을 검사합니다. 코드가 바뀌는 환승은 공급자 구간으로 명시되어야 하며 이름이 같다는 이유로 간선을 만들지 않습니다. 유효하지 않은 응답은 부분 경로를 반환하지 않습니다. 실제 공급자가 다른 환승 구조/역명 정규화를 쓰면 검증 오류로 멈추며 **본인 키의 정상·분기·환승 응답을 확보한 뒤 대응해야 합니다.** 빈 경로도 운행 종료로 해석하지 않습니다. 호출 한도는 실패, 인증 오류는 `awaiting_auth` 후 명시적 재개, 취소는 `cancelled`로 보존합니다. 결과는 60초 후 만료되며 자동 갱신하지 않습니다.

### 경로 결과에서 다음 조회 열기

경로 구간의 출발역·도착역에 **도착 조회 조건 채우기 / 시간표 조건 채우기 / 사물함 설치 조건 채우기**를 제공합니다. 원문 역명과 호선이 도착 참조 목록의 단일 항목과 **정확히 일치할 때만** 후보를 연결합니다. 이는 문자열 일치 후보이며 공급자 간 역 코드 대응을 검증한 것은 아닙니다. `서울역 → 서울`, `02호선 → 2호선` 등의 별칭/호선을 자동 변환하지 않고 미확인 항목에는 역 찾기 링크를 표시합니다. 공급자 역 코드·번호는 조회 입력으로 전달하지 않습니다.

버튼은 기존 조회 초안을 열며 외부 호출·작업·승인을 생성하지 않습니다. 도착 건수·시간표 요일/방향/임시/기존 기준 시각·사물함 크기/건수를 유지하고 설치 검색의 페이지만 1로 되돌립니다. 조회별로 선택한 계정도 유지하며 해제된 계정을 다른 계정으로 바꾸지 않습니다. 권한이 없으면 실행할 수 없습니다.

조회 화면에는 경로의 원문 역명·호선·기준 시각·조회 시각·원래 작업 ID를 출처로 보존합니다. 경로의 시각을 새 시간표 조건에 덮어쓰지 않습니다. 같은 초안을 다시 열어도 출처를 유지하고 역명/호선을 수동 변경하면 안내를 숨깁니다. 만료되거나 실패한 경로 결과는 다음 조회에 적용하지 않습니다. 결과의 실제 지연·운행과 다른 서비스의 제공 구간은 여전히 별도 확인해야 합니다.

## 또타라커·사물함

공식 경로의 구간 역 코드를 보관함 ID로 연결하거나 경로에 설치/빈칸 정보를 자동 합치지 않습니다. 설치 목록과 실시간 빈칸의 제공 범위는 다음과 같습니다.

### 설치 목록 검색

**확장 계획 → 또타라커 → 조회 기능 열기**에서 계정·키 없이 `tlocker.inventory.search`를 실행합니다. 공식 자료는 [서울교통공사 물품보관함 설치수량](https://www.data.go.kr/data/15044235/fileData.do)이며 확인한 원본은 **2026-09-30 기준, 2026-10-06 공개, 341개 보관함 묶음**입니다. 341개는 개별 칸 수가 아닙니다. 설치 목록은 실시간 빈칸 정보가 아닙니다.

```json
{"query":"서울","line":"1","size":"large","page":1,"limit":10}
```

- `query`: 보관함 이름에 포함된 문자열, 1~80자. ‘서울역’→‘서울’ 같은 역명·별칭 변환은 하지 않습니다.
- `line`: 선택 조건, `1`~`9` 또는 `식물원`. 식물원은 시설 분류이며 지하철 노선으로 해석하지 않습니다.
- `size`: `any`(기본)·`small`·`medium`·`large`. 선택 크기의 **설치 수량이 양수**인 묶음으로 좁힙니다. 현재 사용 가능 여부가 아닙니다.
- `page`: 1~1,000, `limit`: 1~50(기본 10). 전체 파일을 검증·검색하고 일치 건수와 다음 페이지를 반환합니다. 검색어·필터는 공급자에게 전송하지 않습니다.

고정 HTTPS 첨부파일 하나만 다운로드하고 리다이렉트·자동 재시도를 하지 않습니다. 30초·1MB 상한, 실제 CP949/UTF-8 판별, 한글 헤더 7개·고유 연번/호선/보관함 이름·음이 아닌 정수 수량을 검증합니다. 페이지 밖 행도 검사하며 깨진 파일을 검색 0건으로 바꾸지 않습니다. **보관함 이름의 번호 구간은 수량으로 환산하지 않습니다.** `서울역23~44` 같은 이름과 실제 크기별 수량은 각각의 원문·열을 따릅니다.

결과의 `installed`·`installedTotal`·`columnCount`는 설치 수량/열입니다. `sourceSerial`은 파일 행의 연번이며 실시간 공급자 ID가 아닙니다. `availableCount`·`providerObservedAt`·`locationDetail`·`operatorLockerId`는 모두 `null`입니다. 원본에 층·출구·위경도·실시간 관측 시각·고장/점유·예약 가능 정보는 없습니다.

검토한 원본은 8,321바이트, SHA-256 `f8f95844cfd1ea0d75e7ceda5f54be80065525b62657d743c0bda9a975c57405`입니다. `snapshot.matchesReviewedFile`이 참일 때만 `snapshot.asOf`에 확인한 기준일을 반환합니다. 고정 주소의 파일이 바뀌어도 구조가 유효하면 설치 목록을 반환하되 **`asOf: null`과 지문 불일치 경고**를 표시합니다. `declaredAsOf`는 등록 시 확인한 출처 고지일이며 변경된 파일의 기준일을 보증하지 않습니다. 새 파일의 실제 기준일·이용 조건·지문은 별도로 검토해 갱신합니다.

검증된 파일은 데이터 폴더의 `locker-cache`(모의 모드 `locker-cache-mock`)에 **7일·파일 1개·원본 1MB, 메타데이터 포함 총 2.1MB**로 보관합니다. 같은 파일의 검색·페이지 이동·재시작은 다운로드 없이 재사용합니다. `retrievedAt`은 파일 다운로드 완료 시각, `queriedAt`은 이번 검색 시각이며 자료 기준일과 구분합니다. 캐시 사용 작업은 `dispatched: false`일 수 있습니다. 검색 결과는 미신뢰 외부 데이터로 취급하고 모의 성공을 지원 실적으로 집계하지 않습니다.

### 앱에서 직접 확인·실시간 조회 후속

**기본 서비스 연결 → 또타라커**에서 [운영사 안내](https://www.smrte.co.kr/support/happybox), Android/iPhone 공식 앱, [설치 수량 공공자료](https://www.data.go.kr/data/15044235/fileData.do)를 선택해 준비 상태를 저장합니다. 사용자가 앱에서 역·크기·현재 빈칸을 직접 확인합니다. 설치 수량은 분기 자료이며 실시간 빈칸이 아닙니다.

`tlocker.availability`는 **비활성 제안 규격**입니다. `stationName/size`를 입력하고 공급자 ID·위치·크기·설치/빈칸 수·관측 시각·고장/미확인 상태를 분리합니다. 없는 빈칸 수는 `null`이며 `0`과 구분합니다. 빈칸 수를 제공하려면 관측 시각·고유 ID·상태·설치 수량과의 관계가 유효해야 합니다. 운영사의 공개 소비자 API를 확인하지 못해 아직 네트워크 호출·키 등록·지원 집계는 하지 않습니다. 자동화는 승인된 조회 경로 확보 후 활성화하며 예약·결제·문 열기는 별도 행동입니다. 앱의 내부 엔드포인트를 추측해 호출하지 않습니다.

## 결과와 후속 검증

두 API는 읽기 행동이며 30초·2MB·UTF-8·JSON/XML 오류 검사, 리다이렉트/자동 재시도 금지, 요청 필터·수신 건수·중복 검사와 공통 계정/클라이언트 권한을 적용합니다. 실제 도착 API 무효 키 응답은 정상 조회의 errorMessage 래퍼 없이 최상위 status/code를 반환했습니다. 이 차이도 처리합니다. 공급자 인증 오류는 인증 대기로 보존해 같은 작업에서 재개하며 오류 본문은 모델에 노출하지 않습니다. 무효 키·빈 응답·서비스 오류를 정상 데이터로 바꾸지 않습니다.

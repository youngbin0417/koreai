# 확장 순서

실행할 작업의 우선순위와 완료 기준은 [다음 할 일](../TODO.md)에서 체크리스트로 관리합니다.

## 구현한 공개 알파 기반

71개 서비스 조사 카탈로그, 21개 공식 API 행동, 5개 생활 서비스 기본 커넥터, 로컬 계정·권한·승인·작업 엔진, MCP/HTTP 인터페이스, 기존 MCP 가져오기, Linux 암호화 저장소, 전용 Chromium 브라우저와 운영자 소유 시험 사이트, 한국어 관리 화면을 제공합니다. Windows 호환 실행은 DPAPI를 유지합니다. 추가 API 후보 26개, 기상청 조회 실행기와 비활성 조회 초안 5개는 [앱·API 확장 계획](APP_API_BACKLOG.md)에서 관리합니다.

공식 서비스의 실제 사용 준비는 각 사용자의 앱 등록·키 발급·심사·계정 검증에 달려 있습니다. 이 코드베이스를 외부 저장소·패키지 레지스트리에 게시하거나 특정 기관에 배포한 상태는 아닙니다.

## 다음 확장

1. 기존 8개와 추가 기상청 커넥터를 실제 계정으로 검증하고 공급자별 오류·권한 차이를 보완합니다.
2. 에어코리아·TAGO·E-Gen의 요청 템플릿에 응답 실행기를 추가하고 나이스·KOBIS의 세부 필드 매핑을 검증합니다. 기상청은 실제 키 검증과 주소→격자 변환을 이어갑니다. 새 API 26개 후보와 71개 서비스의 대표 행동에 공식 근거·제휴 필요 여부·허용 범위를 채웁니다.
3. 허용 범위를 확인한 실제 서비스에 브라우저 레시피를 추가합니다. API와 별도 지원 상태로 유지합니다.
4. 계정 로그인만으로 시작할 수 있도록 운영자 앱 심사·공용 키 비용 관리·간편 설치를 준비합니다.
5. 기기 연결 관리·기관별 계정·권한·실행 기록을 관리형 서비스로 제공합니다.

금융 송금·결제·민원 제출·모바일 앱 조작은 독립 검증과 필요한 공급자 계약·배포 조건을 갖춘 단계에서 추가합니다. 모바일 접근성 API의 자율 행동 제한 등 실제 플랫폼 조건을 확인하고 지원 방식을 결정합니다.

## 추가 구현 후보

강남언니·당근마켓·마켓컬리·쿠팡·토스는 기본 연결을 먼저 제공했습니다. 후속 단계는 조회 기능 정의·검증 → 초안과 사용자 확인 → 승인 후 실행과 결과 확인입니다. 행동별 입력·출력과 실제 작업 범위는 각 단계 착수 시 정의합니다. [기본 연결 문서](LIFESTYLE_CONNECTIONS.md)에 현황과 개발 절차를 유지합니다.

아래는 기존 서비스의 후속 조사 후보입니다. 신규 앱·공개 데이터 API의 우선순위와 이번 초안 적용 범위는 [앱·API 확장 계획](APP_API_BACKLOG.md)에 기록했습니다. 지원 여부와 API 제공 범위는 행동별 문서·계정 검증으로 확정합니다.

| 순서 | 대상 행동 | 다음 조사 작업 |
|---|---|---|
| 1 | 건강보험심사평가원 병원·약국 찾기 | 공공데이터 목록, 검색 항목·갱신 주기·키 신청 확인 |
| 2 | E-Gen 응급의료기관 찾기 | 위치 검색과 실제 운영 정보의 범위·갱신 주기 확인 |
| 3 | 국민건강보험·국민연금 공개 정보 조회 | 공개 정보와 개인 조회·본인확인 권한 구분 |
| 4 | CGV·메가박스 상영 정보 조회 | 공식 제공 경로·제휴 조건 확인, 예매는 별도 행동 |
| 5 | 네이버 예약·캐치테이블 예약 정보 | 소비자 계정의 조회 권한과 제휴 경로 확인 |
| 6 | 코레일·SRT 운행 정보 조회 | 공개 운행 정보와 개인 승차권·결제 권한 구분 |
| 7 | 11번가·G마켓 상품 찾기 | 소비자 검색과 판매자 업무 API 구분 |
| 8 | 네이버 메일·캘린더 기존 정보 조회 | 기존 일정 추가 API와 별도로 조회 제공 여부 확인 |
| 9 | 다음 카페·네이버 블로그 글 작성 | 게시판 권한·작성 API·자동 접근 허용 조건 확인 |
| 10 | 토스·PASS 인증 대기와 재개 | 제휴 계약·인증 콜백·사용자 동의 절차 확인 |

`npm run connector:new -- --id hira-hospitals --service-id hira --name "병원 찾기"`로 행동 규격을 포함한 TypeScript 초안을 만들 수 있습니다. 초안은 비활성 상태이며, 검토 후 `src/connectors/extensions.ts`에 명시적으로 등록합니다. 구현·승인·중복 전송·결과 확인 테스트와 실제 계정 증거를 마련한 뒤 지원 상태를 올립니다.

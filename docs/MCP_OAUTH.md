# 상위 MCP 서버 OAuth 연결

KoreAI 관리 화면에서 외부 **Streamable HTTP MCP 서버**에 로그인하고 선택한 도구를 가져옵니다. OAuth 로그인·토큰 갱신은 공통 엔진에서 처리하며, 에이전트에는 도구와 계정 권한을 별도로 부여합니다. 기존 Bearer 토큰·인증 없는 서버 연결도 유지됩니다.

## 연결 순서

1. **에이전트 연결 → 기존 MCP 서버 가져오기 → ＋ 서버 연결**을 엽니다.
2. 이름·MCP 서버 주소·가져올 정확한 도구 이름을 입력하고 **서비스 OAuth 로그인**을 선택합니다. 도구 이름은 서버 공식 문서에서 확인합니다.
3. 서버가 동적 클라이언트 등록(DCR)을 지원하면 Client ID를 비웁니다. 사전 등록이 필요하면 **등록된 OAuth 클라이언트·권한 설정**에 Client ID를 입력합니다. Client Secret을 사용하는 경우 예상 인증 서버 주소도 반드시 지정합니다. 요청 Scope는 직접 입력한 값 또는 서버의 인증 요구값을 사용하며, 메타데이터에 나열된 모든 권한을 자동 요청하지 않습니다.
4. **OAuth 로그인 준비 → 서비스 로그인 열기**를 누르고 같은 브라우저에서 로그인과 동의를 마칩니다. 로그인 요청은 10분간 유효합니다. 관리 화면의 로그아웃·다른 브라우저·다른 관리 세션에서는 완료할 수 없습니다.
5. 관리 화면으로 돌아와 **OAuth 로그인 완료**와 생성된 계정을 확인합니다. **＋ 에이전트 연결**에서 해당 계정과 필요한 행동을 함께 허용합니다.
6. 도구를 요청한 뒤 **작업과 승인**에서 대상·입력을 확인하고 승인합니다. 외부 도구의 `readOnlyHint`는 승인을 생략하는 근거로 사용하지 않습니다.

페이지를 새로 고쳐 로그인 링크를 잃었으면 **다시 로그인**으로 새 요청을 만드세요. 이전 링크는 무효화됩니다. **로그인 취소**는 대기 중인 로그인 요청을 무효화하며, **연결 해제**는 도구를 중단하고 로컬 자격정보·관련 계정을 제거합니다. 공급자 쪽 동의·토큰을 취소하는 원격 revocation은 구현하지 않았습니다.

## Linux 서버와 휴대폰

사전 등록할 콜백은 관리 화면에 표시된 **MCP OAuth 콜백 주소**입니다. 네이버·카카오 계정 연결의 `/oauth/callback`과 구분합니다.

- 로컬 기본값: `http://127.0.0.1:4318/mcp/oauth/callback`.
- GCP·Tailscale 예시: `https://내기기.내테일넷.ts.net/mcp/oauth/callback`.
- 원격 사용 시 `--public-url`에 고정 HTTPS Origin을 설정하고 **그 주소에서** 로그인을 시작하세요. 임의 Host·요청 본문으로 콜백을 바꿀 수 없습니다. [GCP 설치 안내](GCP_DEPLOYMENT.md).
- 로그인 도중 엔진을 재시작해도 같은 데이터·암호화 키·공개 주소이면 이어서 완료할 수 있습니다. 콜백 Origin이나 포트를 바꿨으면 새 로그인을 시작합니다.
- 휴대폰의 관리 화면과 로그인 창은 같은 브라우저를 사용하세요. 다른 앱 내장 브라우저로 이동하면 쿠키가 공유되지 않을 수 있습니다.

GCP 실제 배포와 공급자·실제 휴대폰 검증은 별도 작업입니다. 이번 검증은 소유한 시험 OAuth/MCP 서버와 Windows Edge의 휴대폰 크기 화면, Linux Node 런타임을 사용했습니다.

## 갱신과 작업 상태

토큰 만료가 가까우면 도구 연결 전에 갱신합니다. 같은 연결의 동시 요청은 갱신을 하나로 합칩니다. 갱신 토큰이 회전하면 새 값을 저장하고, 응답에 새 갱신 토큰이 없으면 기존 값을 유지합니다. **토큰 갱신**으로 수동 복구할 수도 있습니다.

| 상황 | 처리 |
|---|---|
| 전송 전 갱신·초기 인증 실패 | `awaiting_auth`. 도구는 전송하지 않음 |
| 수동 토큰 갱신 성공 | 계정 연결 복구. 대기 작업은 자동 실행하지 않음 |
| 같은 계정으로 대기 쓰기 작업 재개 | `pending_approval`로 돌아가 새 승인 필요 |
| 도구 전송 뒤 401/403·응답 유실 | `needs_review`. 실제 공급자 결과 확인 전 재전송하지 않음 |
| 대화형 재로그인 | 이전 계정·대기 작업 해제 후 새 내부 계정 생성. 기존 에이전트에 새 계정 권한을 다시 부여 |
| 연결 해제 | 도구 중단·계정/로컬 토큰 제거. 이미 전송한 쓰기는 결과 확인 필요 상태 유지 |

재로그인은 공급자에서 다른 계정을 선택할 수 있으므로 기존 계정 권한을 자동 이전하지 않습니다. 토큰 갱신은 같은 내부 계정과 권한을 유지합니다. 상위 SDK의 자동 OAuth 재시도는 사용하지 않아 전송한 도구 요청이 인증 처리 과정에서 다시 발송되지 않습니다.

## 인증정보와 네트워크

- 액세스/갱신 토큰·Client Secret·PKCE verifier는 기존 Vault로 암호화해 SQLite에 저장합니다. Linux는 로컬 AES-256-GCM, Windows는 DPAPI입니다. 데이터와 암호화 키는 같은 사용자 권한으로 보관합니다.
- `state`는 일회용이고 해시로 저장합니다. 콜백은 로그인 시작 세션과 별도의 HttpOnly·SameSite=Lax 증명 쿠키를 검증합니다. 일반 관리 세션의 SameSite=Strict 정책은 유지합니다.
- 도구 설명·결과에서 현재 자격정보를 지우고, 관리 상태 응답에 토큰·Secret·verifier·로그인 URL을 싣지 않습니다. 외부 콘텐츠는 실행 권한이나 승인 조건을 바꿀 수 없습니다.
- Protected Resource Metadata, AS/OIDC 메타데이터, issuer, PKCE S256와 resource 바인딩을 확인합니다. 리소스 메타데이터는 MCP와 같은 Origin, 인증/토큰/등록 엔드포인트는 issuer와 같은 Origin이어야 합니다.
- OAuth 네트워크 요청의 DNS 결과를 검사하고 실제 소켓에 고정합니다. 사설/링크 로컬/예약 주소, HTTP 리디렉션, 1MiB 초과 응답을 거절하고 시간 제한을 적용합니다. 로컬 시험은 **입력한 MCP 서버와 같은 루프백 Origin**만 예외로 허용합니다.

## 현재 호환 범위와 다음 검증

지원: 인증 코드 + PKCE S256, Bearer 토큰, 사전 등록 Client ID, `client_secret_basic`/`client_secret_post` 또는 공개 클라이언트, DCR, 갱신 토큰, Streamable HTTP. 서버가 Protected Resource Metadata를 제공해야 합니다. SDK의 실제 버전과 세부 인증 방식에 따라 공급자별 확인이 필요합니다.

미지원: 자동 Client ID Metadata Document 호스팅, `private_key_jwt`, 클라이언트 인증서 기반 OAuth, 사설망 인증 서버, issuer와 다른 Origin의 토큰/등록 엔드포인트, 쿼리·자격정보를 포함한 서버/메타데이터 URL, 기존 SSE 전용 MCP. 필요한 공급자는 호환성을 확인한 뒤 별도 구현합니다.

[당근 광고 MCP](DAANGN.md#광고-mcp의-별도-후속-연동)와 [토스 운영 콘솔 MCP](TOSS.md#운영-콘솔-mcp의-별도-후속-연결)는 이 엔진의 첫 실제 검증 후보입니다. **등록 조건·실제 로그인·계정/워크스페이스 범위·정확한 도구 이름·한도는 아직 검증하지 않았습니다.** 공통 엔진의 모의 성공을 공급자 지원 수로 집계하지 않습니다. 소비자 중고 물품·개인 금융 API 지원도 별도입니다.

구현 근거: [MCP Authorization 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)와 프로젝트에 설치된 `@modelcontextprotocol/sdk`의 `client/auth.js`·`client/streamableHttp.js`. API 본문과 반환값은 [HTTP·MCP 문서](API.md)를 참고하세요.

# TAGO 도시·정류소·버스 도착

문서 확인·구현일: **2026-10-14**. [버스도착정보](https://www.data.go.kr/data/15098530/openapi.do)의 도시 목록·도착정보와 [버스정류소정보](https://www.data.go.kr/data/15098534/openapi.do)의 이름·번호 검색을 연결합니다. 계정 종류는 `tago-api`입니다.

## 계정 준비

공공데이터포털에서 **국토교통부_(TAGO)_버스도착정보**와 **버스정류소정보**를 각각 활용 신청합니다. 두 서비스의 권한을 갖춘 일반 인증키(Decoding)를 **연결 계정 → 계정 연결 → TAGO 도시·정류소·버스 도착**에 등록하고 필요한 행동을 허용합니다.

서비스별 키가 다르면 같은 `tago-api` 종류의 계정을 두 개 만들고, 도착정보 키에는 도시·도착 조회를, 정류소정보 키에는 정류소 검색만 허용합니다. 계정 저장은 키를 암호화해 보관한 상태이며 실제 공급자 접근은 조회 실행으로 확인합니다.

## 조회 순서

**확장 계획 → TAGO 대중교통**에서 각 행동 이름의 버튼을 선택합니다. 미리보기는 외부 호출·작업 생성·키 조회 없이 동작합니다.

| 순서 | 행동 ID | 입력 예시 | 다음 단계에 사용할 값 |
|---|---|---|---|
| 1 | `tago.cities` | `{}` | `cities[].cityCode` |
| 2 | `tago.bus.stops` | `{"cityCode":25,"name":"송강전통시장"}` | `stops[].nodeId` |
| 3 | `tago.bus.arrivals` | `{"cityCode":25,"nodeId":"DJB8001793"}` | 노선별 도착예정 정보 |

도시와 정류소 값은 실제 조회 결과에서 선택합니다. 예시는 공식 문서의 형식 검토용이며 해당 지역·정류소의 현재 자료 제공을 보증하지 않습니다. 도시 목록은 **도착정보 서비스가 제공하는 지역**입니다. 정류소정보 서비스의 지역별 제공 범위도 실제 키로 확인해야 합니다.

정류소 검색은 `name` 또는 `number`를 입력합니다. 표시 번호(`number`, 예: `44810`)와 조회용 정류소 ID(`nodeId`, 예: `DJB8001793`)를 구분합니다. `number`는 앞자리 0을 보존하는 문자열입니다.

정류소·도착 조회에는 `page`(기본 1, 최대 1,000), `limit`(기본 10, 최대 100)을 사용할 수 있습니다. 도시 목록에는 페이지 입력이 없습니다. 계정을 연결한 뒤 **AI 대화**의 새 대화에서 세 행동을 선택하면 같은 조회 흐름을 요청할 수 있습니다. HTTP·MCP는 기존 행동 실행 인터페이스를 사용합니다.

## 결과 해석

- `stops`: 정류소 ID·이름·표시 번호, 제공된 WGS84 위도·경도. 누락된 위치는 `null`입니다.
- `arrivals`: 노선 ID·번호·유형, 차량 유형, 남은 정류소, `arrivalSeconds`와 `arrivalMinutes`.
- `arrivalSeconds`는 공급자의 초 단위 도착예정 값입니다. `arrivalMinutes`는 표시용 올림 분이며, 816초는 14분으로 표시합니다. 0초는 0분을 유지합니다.
- 예정값이 음수·빈 값·`-`·`null`이면 `arrivalSeconds`와 `arrivalMinutes`는 `null`, `estimateStatus`는 `unavailable`입니다. 같은 노선의 여러 버스는 따로 유지합니다.
- `pagination`은 현재 페이지·전체 수·다음 페이지 여부입니다. 빈 페이지와 자료 없음은 `status: no_data`로 반환합니다. 이 상태를 운행 종료나 미지원 지역으로 확정하지 않습니다.
- `retrievedAt`은 KoreAI가 조회한 시각입니다. 공식 응답에 자료 갱신 시각이 없어 `providerUpdatedAt`은 `null`입니다. 응답을 최신 갱신 시각으로 확대 해석하지 않습니다.
- `source`는 국토교통부 TAGO와 호출한 행동의 공식 근거입니다.

인증 오류는 작업을 `awaiting_auth`로 보존합니다. 해당 API의 활용 신청·권한·키를 확인한 뒤 재개합니다. 한도·IP 접근 거절·통신 실패·취소는 구분하며, 정류소 ID 또는 페이지가 요청과 다르면 `INVALID_RESPONSE`로 중단합니다.

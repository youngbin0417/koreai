# TourAPI 법정동·관광지·축제 조회

확인일: **2026-10-20**. 현재 공공데이터포털 Swagger와 첨부 **국문 활용매뉴얼 v4.4(2026-02-10)**을 기준으로 `KorService2`의 세 조회를 구현했습니다. 본인 승인 키의 정상 응답 검증 전이며 실제 지원 실적으로 집계하지 않습니다.

## 키 등록과 실행 순서

1. [공공데이터포털 국문 관광정보 서비스_GW](https://www.data.go.kr/data/15101578/openapi.do)를 활용 신청합니다. **일반 인증키(Decoding)**를 사용합니다. DeepSeek·KOPIS·KOBIS 키와 별개입니다.
2. KoreAI **연결 계정 → 계정 연결 → TourAPI 국문 관광정보**에서 `serviceKey`를 등록하고 필요한 세 행동을 허용합니다.
3. **확장 계획 → 한국관광 TourAPI → TourAPI 법정동 지역 찾기**로 시도 코드를 찾습니다. `provinceCode`를 지정해 다시 조회하면 그 시도의 시군구 코드를 얻습니다.
4. 지역·관광타입을 **TourAPI 지역 관광정보 조회**, 행사 날짜 조건을 **TourAPI 축제·행사 조회**에 입력합니다. **예시 입력 불러오기 → 요청 구조 미리보기**는 키 조회·외부 호출 없이 동작합니다.

세 행동은 같은 계정 종류 `tourapi-api`를 사용하며 HTTP/MCP에서도 행동·계정 권한을 각각 적용합니다. 키는 서버의 암호화 저장소에 보관하고 호출할 때 `serviceKey` 쿼리에 한 번 인코딩해 넣습니다. 키·원문 공급자 오류·키 포함 URL을 에이전트나 일반 오류로 전달하지 않습니다. Linux의 API 실행에는 브라우저나 그래픽 환경이 필요하지 않습니다.

공식 안내는 개발계정 **일 1,000건**, 개발 자동승인·운영 심의승인을 명시합니다. 본인 키의 실제 승인·트래픽 조건을 확인하세요. 앱 통계에 필요한 `MobileOS=WEB`·`MobileApp=KoreAI`는 실행기가 고정합니다.

## 법정동 지역 찾기

행동: **`tourapi.regions.list`** → `ldongCode2`

시도 목록:

```json
{"page":1,"limit":100}
```

서울의 시군구 목록:

```json
{"provinceCode":"11","page":1,"limit":100}
```

응답의 `regions[].code`와 `name`을 사용합니다. `level`은 `province` 또는 `district`, `provinceCode`는 부모 시도입니다. 시도는 2자리, 시군구는 3자리 문자열입니다. 문서 예시는 서울 `11`·종로구 `110`이며 현재 제공되는 코드는 본인 키의 조회 결과로 확인합니다. 목록 전체가 첫 페이지에 모두 들어온다고 가정하지 않습니다.

**구 TourAPI `areaCode`·`sigunguCode`와 혼용하지 않습니다.** 현재 Swagger는 구 항목을 미사용/삭제 예정으로 표시하고 v4.4 변경 이력은 삭제를 명시합니다. 실행기는 법정동 `lDongRegnCd`·`lDongSignguCd`와 `lDongListYn=N`만 사용합니다. KOPIS 4자리·HIRA 6자리·정보나루 지역 코드도 입력하지 않습니다. 지역명 고정 목록을 내장하지 않고 공급자 목록을 조회합니다.

## 지역 관광정보 조회

행동: **`tourapi.places.search`** → `areaBasedList2`

```json
{
  "provinceCode":"11",
  "districtCode":"110",
  "contentTypeId":"12",
  "sort":"title",
  "page":1,
  "limit":10
}
```

시도·시군구는 선택 조건입니다. 시군구만 지정할 수 없으며 실제 코드 소속은 법정동 조회 결과로 확인합니다. `contentTypeId` 기본값은 `12` 관광지입니다.

| 타입 | 분류 | 타입 | 분류 |
|---|---|---|---|
| `12` | 관광지 | `14` | 문화시설 |
| `15` | 축제공연행사 | `25` | 여행코스 |
| `28` | 레포츠 | `32` | 숙박 |
| `38` | 쇼핑 | `39` | 음식점 |

콘텐츠 ID·타입·이름·주소·전화·우편번호·법정동 코드·좌표 원문과 제공된 수정 시각을 반환합니다. 숙박·쇼핑·음식점도 공개 관광 목록 조회이며 개인 예약·주문 내역 접근은 제공하지 않습니다.

## 축제·행사 조회

행동: **`tourapi.festivals.search`** → `searchFestival2`

```json
{
  "eventStartDate":"2026-01-01",
  "eventEndDate":"2026-12-31",
  "provinceCode":"11",
  "sort":"modified",
  "page":1,
  "limit":10
}
```

`eventStartDate`는 필수, `eventEndDate`는 선택입니다. 실제 달력의 `YYYY-MM-DD`를 받고 공급자에게 `YYYYMMDD`로 전달합니다. 종료일 조건은 시작일 조건 이후 또는 같은 날이어야 합니다. KOPIS의 최대 31일 제한을 적용하지 않습니다. 화면 예시는 **Asia/Seoul 현재 연도**의 1월 1일~12월 31일입니다.

**입력한 기간과 겹치는 모든 행사를 찾는 기능으로 해석하지 않습니다.** 공식 문서는 행사시작일·행사종료일이라는 설명만 제공하며 포함/겹침 경계를 충분히 명시하지 않습니다. 본인 키로 이미 진행 중인 장기 행사·경계 날짜·기간 전후 사례를 대조해야 합니다. 실행기는 두 조건을 그대로 전달하고 응답 기간을 잘라내거나 임의로 다시 필터링하지 않습니다.

행사의 `startDate`·`endDate`와 `progressTypeRaw`(취소·연기 등의 공급자 원문), `festivalTypeRaw`를 반환합니다. 날짜만 보고 현재 개최 중이라고 판정하지 않으며 `currentlyHappening`은 `null`입니다. 날짜 누락·`00000000`은 미확인으로 보존합니다.

## 공통 결과와 한계

- `sort`: `title`·`modified`·`created`를 공급자 `A`·`C`·`D`에 매핑합니다. 이미지 필수 정렬을 사용하지 않습니다.
- `page`는 1~1,000, `limit`는 1~100이며 기본 1·10입니다. 이는 KoreAI의 실행 제한이며 공급자의 최대 허용값으로 주장하지 않습니다. 한 페이지만 호출하고 다음 페이지는 별도 요청합니다.
- `pagination`의 페이지·크기·전체 수와 행 수를 대조합니다. 메타데이터가 요청과 다르면 실패합니다. 첨부 예제 일부에서 요청 크기와 응답 `numOfRows`가 일치하지 않으므로 실제 계정의 반환 규칙 확인을 검증 항목으로 남깁니다.
- 정상 빈 페이지는 `no_data`와 공급자 전체 수를 반환합니다. `03` 자료 없음 헤더에 페이지 정보가 없으면 `totalCount: null`입니다. 빈 결과를 폐업·행사 취소·매진으로 판정하지 않습니다.
- GPS X/Y는 WGS84 경도/위도(`EPSG:4326`)입니다. 원문 정밀도를 `coordinates.raw`에 보존하고 둘 다 0이거나 한쪽이 없으면 위경도는 `null`입니다. 다른 좌표계로 추정 변환하지 않습니다.
- `createdAtRaw`·`providerUpdatedAtRaw`는 공급자 시각 원문입니다. 시간대를 붙이지 않습니다. `retrievedAt`은 조회 시각, 최상위 `providerUpdatedAt`은 `null`입니다.
- `currentlyOpen`·`reservationAvailable`은 `null`입니다. 현재 영업·개최·운영시간·최종 요금·좌석·예약 가능 여부를 확인하지 않습니다.
- `copyrightTypeRaw`와 `source.attribution`을 보존합니다. KoreAI는 한국관광공사 출처를 함께 표시하도록 안내합니다. 사진은 Type1·Type3 등 조건이 다르므로 첫 구현은 이미지 URL·이미지 다운로드를 제공하지 않습니다. 텍스트 조회 성공을 사진 재사용 허용으로 확대하지 않습니다.

## 오류와 검증 상태

HTTPS **`https://apis.data.go.kr/B551011/KorService2/`**만 사용하며 HTTP 대체·리다이렉트 재전송을 하지 않습니다. 고의로 무효인 시험 키로 세 경로 모두 **HTTP 403·JSON 게이트웨이 코드 30**을 확인했습니다. 실제 오류는 구 문서의 ‘XML로만 출력’ 설명과 다르므로 JSON/XML 게이트웨이 오류와 정상 헤더 오류를 모두 처리합니다.

HTTP 401/403과 인증 관련 공급자 코드(`20`·`21`·`30`·`31`·`32`·`33`)는 `인증 필요`로 보존합니다. 키·승인 조건을 수정한 뒤 같은 작업을 재개할 수 있습니다. `22`·`23`·HTTP 429는 호출 한도, `29`는 IP 차단 오류로 구분합니다. 알려지지 않은 코드는 의미를 추정하지 않습니다.

정상 코드 `00`·`0000`, 30초 제한·취소·2MB 스트림 제한·UTF-8/XML·페이지·중복 ID·타입/법정동·날짜/좌표를 검증합니다. XML DTD/엔티티를 거절하고 불필요한 추가 필드를 결과로 전달하지 않습니다. 공급자 내용은 엔진에서 `external_data`로 표시합니다. 모의 성공이나 무효 키 오류로 실제 지원 수를 올리지 않습니다.

모의 단위/HTTP·모바일 크기 화면·Linux 엔진·실제 무효 키 호출의 범위는 [검증 기록](VALIDATION.md#2026-10-20-tourapi-관광정보-조회-검증)에 구분합니다. 본인 키의 정상/빈 응답·지역 필터·페이지 크기·축제 날짜 의미·운영 조건 검증과 실제 휴대폰 기기 시험은 남아 있습니다.

후속 TourAPI 기능은 상세·키워드·위치·신분류 코드 탐색입니다. 다음 신규 서비스는 **식품안전나라 회수·판매중지 정보**의 공식 API ID·필드·인증·HTTPS 확인입니다. [작업 체크리스트](../TODO.md)

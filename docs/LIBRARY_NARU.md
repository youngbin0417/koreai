# 정보나루 도서관·소장 조회

확인일 **2026-10-19**. 공식 API 매뉴얼 **v20260620**의 도서관 목록, ISBN 소장 도서관, 개별 소장·대출 제공값 조회를 구현했습니다. 모든 호출은 고정된 HTTPS 주소를 사용합니다. 무효 시험 키의 인증 오류는 실제로 확인했으며, 유효한 사용자 키의 정상·빈 결과는 아직 모의 응답으로 검증했습니다.

## 연결과 사용 순서

1. [도서관 정보나루](https://www.data4library.kr/)에 가입하고 마이페이지에서 **Open API 인증키**를 신청하여 승인을 확인합니다. 네이버·공공데이터포털 키와 다릅니다.
2. KoreAI **연결 계정 → 도서관 정보나루**에서 `apiKey`로 저장하고 필요한 조회 행동을 허용합니다. 공급자에는 `authKey`로 전송됩니다. 에이전트·대화에도 원하는 행동과 해당 계정을 허용합니다.
3. **확장 계획 → 도서관 정보나루**에서 예시를 불러와 미리보기로 요청 구조를 확인합니다. 이 단계는 키 조회·외부 호출·작업 생성을 하지 않습니다.
4. 도서관 찾기의 `libraryCode`, [네이버 도서 검색](NAVER_BOOKS.md)의 `isbn13`을 아래 후속 조회 입력으로 사용합니다. 실행 요청에서 실제 공급자 호출이 발생합니다.

Linux 서버에서 직접 호출하므로 GUI 브라우저·사용자 사이트 로그인은 필요하지 않습니다. 서버의 암호화 저장소에 키를 등록하고 휴대폰에서는 기존 HTTPS 관리 주소에 접속합니다. 이 구현은 실제 GCP 배포·휴대폰 기기 시험을 포함하지 않습니다.

| 행동 | 공식 HTTPS 요청 | 주요 입력 |
|---|---|---|
| `library-naru.libraries.search` | `GET https://data4library.kr/api/libSrch` | 선택 `region`, `district`, `libraryCode`; `page`, `limit` |
| `library-naru.collections.search` | `GET https://data4library.kr/api/libSrchByBook` | 필수 `isbn`, `region`; 선택 `district`, `page`, `limit` |
| `library-naru.book.status` | `GET https://data4library.kr/api/bookExist` | 필수 `isbn`, `libraryCode` |

```json
{"region":"11","district":"11010","page":1,"limit":10}
```

```json
{"isbn":"9791191056556","region":"11","page":1,"limit":10}
```

```json
{"isbn":"9791191056556","libraryCode":"050001"}
```

예시는 공식 매뉴얼의 코드·ISBN을 이용한 형식 예시이며 실제 소장·대출 가능 여부를 보증하지 않습니다. `libraryCode`는 도서관 찾기 결과의 **6자리 문자열**이며 앞자리 0을 보존합니다. `isbn`은 체크 숫자가 유효한 **ISBN-13 문자열**이어야 합니다. 공백·하이픈을 제거하며 ISBN-10은 이 API에 보내지 않습니다. 소장 도서관 요청의 공급자 필드는 `isbn`, 개별 소장 요청은 `isbn13`입니다.

`page`는 1~10,000(기본 1), `limit`은 1~100(기본 10)으로 제한합니다. 이 범위는 KoreAI의 실행 제한입니다. `pagination.nextPage`가 있으면 같은 조건의 후속 페이지를 요청합니다. 도서관 이름 검색과 자동 전체 페이지 수집은 구현하지 않았습니다. 빈 결과는 `no_data`로 반환하며 도서관 폐관·책 절판·다른 판본의 미소장으로 판단하지 않습니다.

## 지역 코드

정보나루의 코드 체계를 사용합니다. 일반 행정구역·다른 API의 코드와 구분하세요.

| 지역 | 코드 | 지역 | 코드 | 지역 | 코드 |
|---|---|---|---|---|---|
| 서울 | `11` | 부산 | `21` | 대구 | `22` |
| 인천 | `23` | 광주 | `24` | 대전 | `25` |
| 울산 | `26` | 세종 | `29` | 경기 | `31` |
| 강원 | `32` | 충북 | `33` | 충남 | `34` |
| 전북 | `35` | 전남 | `36` | 경북 | `37` |
| 경남 | `38` | 제주 | `39` | | |

`district`는 공식 세부지역 코드 5자리입니다. 예: 종로구 `11010`, 서초구 `11220`, 강남구 `11230`. 지역과 함께 입력하면 앞 두 자리가 일치해야 합니다. 전체 세부지역의 유효성은 공급자가 확인하며, 코드 이름 찾기 기능은 후속 작업입니다.

## 결과의 범위와 자료 시점

도서관 목록은 이름·주소·전화·홈페이지·운영시간/휴관일 원문·제공된 좌표와 단행본 수를 반환합니다. 누락값은 `null`, 도서관 코드와 연락처는 문자열로 보존합니다. 좌표 한 축이 없거나 둘 다 0이면 좌표를 미확인으로 표시합니다. 홈페이지나 표지에 대한 추가 HTTP 요청은 수행하지 않습니다. 운영 일정으로 현재 개관 여부를 계산하지 않습니다(`currentlyOpen: null`).

개별 소장 결과는 다음을 구분합니다.

| 필드 | 의미 |
|---|---|
| `hasBook` | 해당 도서관·ISBN의 공급자 소장 제공값 |
| `loanAvailableReported` | 공급자가 반환한 대출 상태. 미제공이면 `null` |
| `currentLoanAvailable` | 항상 `null`: 현재 대출 가능 여부 미확인 |
| `loanStatusBasis` | `previous_day_per_api_manual`: API 매뉴얼은 전날 상태로 설명 |
| `loanStatusDate`·`providerUpdatedAt` | 실제 자료 기준일·갱신 시각이 없어 `null` |
| `retrievedAt` | KoreAI가 조회한 시각. 자료 갱신 시각과 다름 |

공식 API 매뉴얼 35쪽·[개선 공지](https://data4library.kr/noticeV?cn=129)는 대출 상태를 전날 기준으로 설명합니다. [MCP 웹 안내](https://www.data4library.kr/mcpUtilization)는 소장 자료가 월 단위로 갱신되어 현재 재고와 시차가 있을 수 있다고 설명합니다. 둘을 같은 기준시각으로 합치거나 정확한 어제 날짜를 응답의 자료일로 생성하지 않습니다. 결과에 실제 자료 기준일이 없으면 미제공 상태를 유지합니다. 다른 판본·전자책의 소장, 개인 회원의 대출 자격·내역·예약·연장은 포함하지 않습니다.

## 인증·오류·전송

- 공식 세 XML 경로의 HTTPS 접속과 HTTP 200의 `authErr`를 무효 시험 키로 확인했습니다. API 매뉴얼의 예시는 HTTP지만 실행기는 HTTPS만 사용하며 HTTP로 재시도하지 않습니다.
- `authErr` 또는 HTTP 401·403은 `awaiting_auth`로 보존합니다. 승인 키·등록 서버 IP·이용 조건을 확인하고 같은 작업을 재개합니다. HTTP 429는 한도 오류, 다른 공급자 오류는 본문·키·URL 없이 표시합니다.
- MCP 매뉴얼 v20260825는 서버 IP 등록 시 일 30,000건, 최대 IP 3개, API·MCP 사용량 통합 집계를 안내합니다. 실제 본인 계정의 승인·IP·현재 한도를 확인해야 합니다. 여러 개별 대출 조회는 각각 호출량을 사용합니다.
- XML 응답은 2MB·30초로 제한하고 DTD/엔티티 선언·리다이렉트·잘못된 UTF-8을 거절합니다. 페이지·개수·중복 도서관 코드·개별 조회의 도서관/ISBN 에코가 맞지 않으면 실패로 중단합니다.
- 키는 비밀 저장소에서 주입합니다. 모델 입력에 키·임의 URL을 받을 수 없으며 결과에는 공급자의 키 에코·알 수 없는 추가 필드를 전달하지 않습니다. 반환된 외부 데이터는 계정 권한·승인 규칙을 변경하지 못합니다.

## 공식 MCP와 후속 작업

[공식 MCP 매뉴얼](https://www.data4library.kr/downloadMcpManual)은 `https://www.data4library.kr/mcp`와 `X-Auth-Key` 헤더를 안내합니다. `search_libraries`, `get_library_collection`, `check_book_availability`는 이번 직접 API 조회에 대응합니다. 이름·지역 코드 탐색 도구도 별도로 있습니다.

현재 KoreAI 상위 MCP 연결 화면의 Bearer/OAuth 인증과 이 사용자 정의 헤더는 다릅니다. MCP용 키를 도구 입력에 넣거나 일반 Bearer 토큰으로 대체하지 않습니다. 정보나루 MCP의 비밀 헤더 주입·실제 도구 권한·계정 검증은 별도 후속 작업으로 남깁니다. 이번 API 행동은 KoreAI의 기존 HTTP·로컬 MCP 인터페이스로 사용할 수 있습니다.

다음 개발 후보는 도서관 이름·지역 코드 탐색과 **네이버 책 검색 → ISBN 선택 → 소장 도서관 → 대출 제공값**을 연결하는 사용자 흐름입니다. 먼저 본인 승인 키의 정상/빈 응답·서버 IP·한도·지역별 제공 범위를 확인합니다. 이후 HIRA·KOPIS의 첫 조회 구현을 이어갑니다.

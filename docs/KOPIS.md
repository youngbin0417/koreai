# KOPIS 공연 검색·상세 조회

확인일: **2026-10-19**. 공연예술통합전산망 공식 개발 가이드 **v5.0(2026-04-23)**의 두 조회를 구현했습니다. 본인 인증키의 정상 응답 검증 전이며 실제 지원 실적으로 집계하지 않습니다.

## 계정 연결과 실행

1. PC에서 [KOPIS Open API 안내](https://kopis.or.kr/por/cs/openapi/openApiInfo.do?menuId=MNU_00077)의 **인증키 발급신청**을 진행합니다. 본인 이메일로 받은 키를 사용합니다. 영화 KOBIS·공공데이터포털 키와 다릅니다.
2. KoreAI **연결 계정 → 계정 연결 → KOPIS 공연정보**에서 `apiKey`를 등록하고 **KOPIS 공연 검색·KOPIS 공연 상세 조회**를 허용합니다.
3. **확장 계획 → KOPIS 공연정보**에서 행동을 선택합니다. **예시 입력 불러오기 → 요청 구조 미리보기**는 키 조회·외부 호출 없이 동작합니다.
4. 검색 결과의 `performanceId`를 상세 입력에 넣습니다. HTTP/MCP에서도 같은 행동·계정 권한을 사용합니다. API만 사용하는 Linux 서버에는 브라우저나 그래픽 환경이 필요하지 않습니다.

KOPIS는 1인 1키 발급과 키 양도·공유 금지를 안내합니다. 키는 로컬 암호화 저장소에 보관하고 요청 시 공급자의 `service` 쿼리에만 주입합니다. 호출한 에이전트·미리보기·일반 오류에 키를 반환하지 않습니다. 사용량 제한은 본인 키의 운영 조건을 확인해야 하며 검증하지 않은 일일 숫자를 가정하지 않습니다.

## 공연 검색

행동: **`kopis.performances.search`** · 계정 종류: **`kopis-api`**

```json
{
  "startDate": "2026-10-19",
  "endDate": "2026-10-25",
  "regionCode": "11",
  "districtCode": "1168",
  "genreCode": "GGGA",
  "page": 1,
  "limit": 10
}
```

| 입력 | 조건 |
|---|---|
| `startDate`, `endDate` | 실제 달력의 `YYYY-MM-DD`. 양 끝을 포함해 최대 31일, 종료일은 시작일 이후 또는 같은 날 |
| `name`, `venue` | 선택 공연명·공연시설명, 각 1~100자 |
| `regionCode` | 선택 KOPIS 시도 코드. 서울 `11`, 부산 `26`, 경기 `41`, 강원 `51` 등 17개 |
| `districtCode` | 선택 KOPIS 구군 4자리. 종로 `1111`, 서초 `1165`, 강남 `1168`. 앞 두 자리가 같은 `regionCode` 필수 |
| `genreCode` | 선택 장르 코드, 아래 9개 |
| `state` | 선택 `01` 공연예정·`02` 공연중·`03` 공연완료 |
| `page`, `limit` | 각각 1~999·1~100, 기본 1·10 |

장르: `AAAA` 연극, `BBBC` 무용(서양/한국무용), `BBBE` 대중무용, `CCCA` 서양음악(클래식), `CCCC` 한국음악(국악), `CCCD` 대중음악, `EEEA` 복합, `EEEB` 서커스/마술, `GGGA` 뮤지컬.

지역·장르는 공식 공통 코드 PDF의 확인일 기준 목록입니다. `45`의 명칭은 해당 표의 ‘전라북도’를 보존했습니다. 응답의 지역·장르 명칭은 공급자 원문으로 반환합니다. 구군은 형식·시도 접두사만 검증하므로 실제 코드 존재 여부는 공식 표로 확인하세요. 정보나루·HIRA 지역 코드와 혼용하지 않습니다.

화면의 검색 예시는 **Asia/Seoul 오늘부터 7일**을 요청 시 계산합니다. 위 고정 날짜에 자료가 존재함을 보장하지 않습니다.

응답은 한 페이지의 `performances`와 `pagination`입니다. 전체 건수·응답 페이지 번호는 공급자가 제공하지 않습니다. `page`·`limit`는 요청 값이며 `totalCount`는 `null`입니다. 가득 찬 페이지의 `nextPageCandidate`는 조회할 후보이고 `hasMore: null`은 다음 페이지 존재가 미확인이라는 뜻입니다. 마지막 허용 페이지 999에서는 후보를 만들지 않습니다. 덜 찬 페이지는 `hasMore: false`로 표시합니다. 검색 기간에 걸치는 장기 공연의 시작·종료일을 요청 기간으로 잘라내지 않습니다.

## 공연 상세

행동: **`kopis.performances.get`**

```json
{"performanceId":"PF132236"}
```

`performanceId`는 검색에서 받은 `PF`와 6~10자리 숫자입니다. 위 ID는 문서의 형식 예시이며 현재 공연·자료 존재를 보장하지 않습니다. 임의 URL·경로·인증키를 입력할 수 없습니다. 상세의 ID가 요청과 다르거나 여러 행이면 실패합니다.

주요 결과:

- 공연 ID·이름·기간·공연장·지역/장르 원문, 공급자 공연 상태와 오픈런 제공값.
- 시설 `facilityId`·공연장 `venueId`, 출연/제작진·시간/연령·줄거리 원문.
- `ticketPriceGuidanceRaw`·`scheduleGuidanceRaw`: 가격·시간 안내 원문. 회차별 실시간 판매 가격·예약 가능 여부는 확인하지 않습니다. `currentSeatsAvailable`은 `null`입니다.
- `registeredAtRaw`·`providerUpdatedAtRaw`: 공급자의 등록/수정 시각 원문. 표기되지 않은 시간대를 붙이지 않습니다. 최상위 `retrievedAt`은 조회 시각, `providerUpdatedAt`은 `null`입니다.
- `ticketLinks`: 예매처 이름과 정상적인 HTTP(S) 주소만 반환합니다. 자격정보 포함 URL·다른 프로토콜은 제외하고 링크를 따라가거나 예매·결제하지 않습니다. 포스터·소개 이미지는 다운로드하거나 결과에 포함하지 않습니다.

빈 목록은 `no_data`, 빈 상세는 `performance: null`입니다. 이를 취소·삭제·매진으로 판정하지 않습니다. 상세의 예매처 중첩 구조는 공식 필드 설명을 바탕으로 구현했으며 본인 키 응답으로 구조와 선택 필드를 확인해야 합니다.

## 출처 표시

KOPIS는 자료를 활용한 서비스에 출처 표시를 요구합니다. 결과의 `source.attribution`을 요약·재표시에도 함께 표시하세요.

> 출처: (재)예술경영지원센터 공연예술통합전산망(kopis.or.kr)

공연 기간·상태·안내 가격이 현재 좌석·회차·최종 결제 조건을 보장하지 않는다는 `dataNote`도 함께 전달합니다.

## 전송과 실패 처리

정규 주소 **`https://kopis.or.kr/openApi/restful/pblprfr`**에 직접 요청합니다. 공식 PDF의 HTTP 주소와 달리 HTTPS 정상 접속을 확인했습니다. `https://www.kopis.or.kr`의 같은 경로는 정규 주소로 301 이동하므로 사용하지 않습니다. 키가 포함된 요청의 리다이렉트·HTTP 대체 요청은 하지 않습니다.

- **실제 확인:** 고의로 무효인 시험 키로 검색·상세 모두 HTTP **200** 안의 `<returncode>02</returncode>`를 받았습니다. `AUTH_REQUIRED`·`awaiting_auth`로 보존하고 키를 수정한 뒤 같은 작업을 재개할 수 있습니다.
- 다른 공급자 코드는 의미를 추정하지 않고 `PROVIDER_숫자` 또는 `PROVIDER_ERROR`로 실패합니다. HTTP 401/403은 인증 대기, 429는 호출 한도 오류입니다. 원문 오류·키 포함 URL을 노출하지 않습니다.
- 30초 시간 제한·사용자 취소·2MB 응답 제한·UTF-8·XML 구조·중복 ID·건수·날짜·상세 ID를 검증합니다. DTD/외부 엔티티 선언은 거절합니다.
- 페이지 내용은 엔진에서 `external_data`로 취급합니다. 응답 안의 지시문이 계정·행동 권한을 바꾸지 못합니다.
